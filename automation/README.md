# Lab AI Operating Model

This folder describes how the lab's AI-assisted work runs.

## Recommendation

- Cadence: weekly
- Output: one focused cycle at a time
- Rule: AI can research, draft, and prepare build work, but it cannot publish without approval
- Target: only `lab.zuhaib.pro`

## Cycle flow

1. Signal intake
   - capture a real problem, a user, or a workflow friction
2. Problem framing
   - turn the signal into a buildable brief
3. Research support
   - collect notes, references, and constraints
4. Prototype draft
   - create the first build direction and page structure
5. Human review
   - keep the approval gate with Zuhaib
6. Publish
   - push only when the cycle is ready for `lab.zuhaib.pro`

## What AI does

- summarize research
- draft brief copy
- propose page structure
- prepare build checklists
- draft launch notes

## What Zuhaib approves

- the problem to solve
- the audience
- the product direction
- the voice and tone
- the deploy signal

## What the first cycle needs

- one real problem area or workflow
- the intended user
- one example of friction or pain
- any hard constraints
- approval to move from brief to prototype

## Output per cycle

- brief
- research notes
- decision log
- build plan
- high-fidelity visual reference
- review pack
- publish-ready summary

## Visual reference rule

Every future experiment must include at least one high-fidelity UI reference before it is review-ready.

The visual reference should show the expected product screen, not only an abstract moodboard. It must answer:

- what the product looks like
- what the user sees first
- what the main workflow feels like
- what will appear on `lab.zuhaib.pro` after approval
